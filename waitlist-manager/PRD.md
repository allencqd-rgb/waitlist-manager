# 演出候补递补管理系统 — 产品需求文档（PRD）

> 版本：v2.0  
> 更新日期：2026-05-25  
> 状态：已开发完成，持续迭代

---

## 1. 产品概述

### 1.1 背景

演出业务中，员工通过候补方式登记观演意向，当有名额释放时需要按规则将候补人员递补入场。原流程依赖人工 Excel 管理，存在以下痛点：

- 候补数据分散，无法实时掌握各剧目候补与递补状态
- 递补操作依赖人工比对，效率低且易出错
- 人员多剧目候补时，递补后其他候补记录需人工逐条取消
- 缺乏剧目维度的数据统计，难以快速决策

### 1.2 产品定位

一款面向演出运营人员的**轻量级候补递补管理工具**，支持候补数据录入、剧目维度管理、拖拽式递补操作、数据导入导出，核心解决「递补操作效率」和「数据准确性」问题。

### 1.3 目标

- 递补操作从手动比对提升为**拖拽一键完成**
- 递补后自动取消同人员其他候补，**零遗漏**
- 剧目维度实时统计，**秒级掌握全局**
- 支持批量导入导出，**无缝衔接现有 Excel 工作流**

## 2. 用户角色

| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| 运营人员 | 负责候补名单管理和递补操作 | 快速找到候补人员、一键递补、导出结果 |
| 管理者 | 需要查看候补/递补统计数据 | 各剧目候补人数、递补进度一目了然 |

## 4. 功能详细描述

### 4.1 数据录入

#### 4.1.1 手动添加记录

| 项目 | 说明 |
|------|------|
| 入口 | 导航栏「＋ 添加记录」按钮 |
| 表单字段 | 工号（必填）、演出名称（必填）、城市（必填）、候补日期（必填） |
| 去重规则 | 按「工号 + 演出名称 + 城市 + 候补日期」四元组去重，已存在时弹窗提示 |
| 自动填充 | 候补创建时间 = 添加时刻（ISO 格式），状态 = 候补中，已递补至 = 空 |

#### 4.1.2 CSV 批量导入

| 项目 | 说明 |
|------|------|
| 入口 | 导航栏「📥 导入」按钮 |
| 支持格式 | .csv 文件 |
| 交互方式 | 点击选择文件 或 拖拽文件到上传区域 |
| 列映射 | 自动读取 CSV 表头，识别「工号」「演出名称」「城市」「候补日期」「候补创建时间」列 |
| 去重逻辑 | 逐条与现有数据按四元组去重，跳过重复记录 |
| 结果反馈 | 弹窗显示：成功导入 X 条，跳过重复 Y 条 |

### 4.2 候补管理

#### 4.2.1 候补名单表格

| 项目 | 说明 |
|------|------|
| 展示字段 | 工号、演出名称、城市、候补日期、状态、候补创建时间 |
| 排序 | 点击表头字段可切换升序/降序，当前排序字段显示箭头指示 |
| 搜索 | 按演出名称模糊搜索、按城市模糊搜索 |
| 标签页 | 全部 / 候补中 / 已递补，切换时右侧显示对应数量徽章 |
| 空状态 | 无数据时显示空状态插图和引导文字 |

#### 4.2.2 取第一志愿筛选

| 项目 | 说明 |
|------|------|
| 入口 | 筛选栏「○ 取第一志愿」按钮 |
| 规则 | 开启后，每工号只保留**候补创建时间最早**的一条候补记录 |
| 已递补记录 | 不受第一志愿筛选影响，全部保留 |
| 视觉反馈 | 按钮变紫色高亮，表格和剧目卡片区域显示紫色提示条 |
| 导出 | 导出下拉菜单新增「导出第一志愿结果」选项 |

---

### 4.3 递补操作

#### 4.3.1 拖拽递补

| 项目 | 说明 |
|------|------|
| 操作方式 | 从左侧候补表格拖拽一行记录，放到右侧剧目卡片 或 左侧蓝色剧目标签区域 |
| 前置校验 | 仅「候补中」状态的记录可被拖拽递补 |
| 拖拽视觉 | 拖拽行半透明，目标区域高亮蓝色边框并显示「松开鼠标完成递补」提示 |
| 确认弹窗 | 显示工号、目标剧目名称/城市/日期，提示递补后其他候补将被取消 |
| 数据兼容 | 同时设置 `application/json` 和 `text/plain` 两种拖拽数据格式，兼容不同浏览器 |

#### 4.3.2 剧目一致性校验

| 项目 | 说明 |
|------|------|
| 校验规则 | 候补记录的原始剧目（演出名称+城市+候补日期）必须与目标剧目完全一致 |
| 不匹配处理 | 弹出「❌ 剧目不匹配」提示，显示原始剧目和目标剧目的详细信息，阻止递补 |
| 适用范围 | 左侧蓝色剧目标签区域 + 右侧剧目卡片区域，两处拖拽目标均生效 |

#### 4.3.3 级联取消

| 项目 | 说明 |
|------|------|
| 规则 | 递补完成后，该工号的其他候补记录自动标记为「已取消」 |
| 已递补至字段 | 取消的记录填写「同一人员已递补至[工号]剧目信息」说明原因 |
| 影响范围 | 所有其他「候补中」状态的记录，不限剧目 |

### 4.4 剧目管理

#### 4.4.1 剧目卡片

| 项目 | 说明 |
|------|------|
| 分组规则 | 按演出名称+城市+候补日期自动分组 |
| 实时统计 | 每个卡片显示「候补中 X人」「已递补 X人」 |
| 展开/收起 | 点击卡片展开查看已递补人员列表（工号、递补时间），再次点击收起 |
| 拖拽接收 | 卡片区域为拖拽目标，松开即触发递补流程 |
| 空状态 | 无剧目数据时显示空状态插图和引导文字 |

#### 4.4.2 右键删除剧目

| 项目 | 说明 |
|------|------|
| 入口 | 左侧蓝色剧目标签区域，右键点击剧目标签 |
| 操作菜单 | 弹出上下文菜单，显示剧目信息，点击「删除」 |
| 二次确认 | 确认框显示：剧目名称、城市、日期、将删除的记录数量、不可撤销警告 |
| 删除范围 | 删除该剧目下所有「候补中」的记录，**已递补记录保留** |
| 已删除标记 | 剧目卡片显示红色边框 + 半透明 + 红色「已删除」标签，候补人数归零 |
| 已递补保留 | 已删除剧目的已递补人员列表仍可展开查看 |

#### 4.4.3 已删除剧目展示

| 项目 | 说明 |
|------|------|
| 视觉样式 | 红色边框、半透明（opacity-70）、红色「已删除」标签 |
| 统计数据 | 候补人数归零，已递补人数保留实际值 |
| 交互 | 仍可展开查看已递补人员列表 |
| 生命周期 | 删除标记持久化至 LocalStorage，刷新页面不丢失 |

## 5. 数据模型

### 5.1 候补记录（Entry）

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| id | string (UUID) | 唯一标识 | "a1b2c3d4-..." |
| 工号 | string | 员工工号 | "A001" |
| 演出名称 | string | 剧目名称 | "歌剧魅影" |
| 城市 | string | 演出城市 | "上海" |
| 候补日期 | string | 候补的演出日期 | "2026-06-01" |
| 候补创建时间 | string (ISO) | 记录创建时间 | "2026-05-25T10:00:00.000Z" |
| 状态 | string | 候补中 / 已递补 / 已取消 | "候补中" |
| 已递补至 | string \| null | 递补目标剧目信息 | "歌剧魅影\|上海\|2026-06-01" |
| 递补时间 | string (ISO) \| null | 递补操作时间 | "2026-05-25T11:00:00.000Z" |

### 5.2 去重键

```
唯一键 = 工号 + 演出名称 + 城市 + 候补日期
```

### 5.3 剧目组合（ShowCombination）

由候补记录自动聚合，非独立实体：

| 字段 | 类型 | 说明 |
|------|------|------|
| 演出名称 | string | 剧目名称 |
| 城市 | string | 演出城市 |
| 候补日期 | string | 演出日期 |
| 候补人数 | number | 候补中人数 |
| 已递补人数 | number | 已递补人数 |

### 5.4 已删除剧目（deletedShows）

```
Set<string>  // 存储剧目key: "演出名称|城市|候补日期"
```

## 7. 交互流程

### 7.1 拖拽递补流程

```
用户拖拽候补行
  → 浏览器触发 dragStart（设置 JSON 数据）
  → 拖拽至剧目卡片/标签上方（高亮反馈）
  → 松开鼠标（drop 事件）
  → 解析拖拽数据
  → 校验状态：仅「候补中」可递补
  → 校验剧目一致性：原始剧目 == 目标剧目？
     → 不一致 → 弹出「剧目不匹配」提示 → 结束
     → 一致 → 继续
  → 弹出确认框（显示工号、剧目信息、警告）
     → 取消 → 结束
     → 确认 → 执行递补
       → 该记录：状态=已递补，已递补至=剧目key，递补时间=当前时间
       → 同工号其他记录：状态=已取消，已递补至=原因说明
  → 保存数据 → 界面实时刷新
```

### 7.2 CSV 导入流程

```
用户点击「导入」→ 弹出导入弹窗
  → 选择/拖拽 CSV 文件
  → 自动解析表头和行数据
  → 逐条去重检查
  → 弹窗显示结果：成功 X 条，跳过重复 Y 条
  → 数据保存 → 表格和卡片实时刷新
```

### 7.3 订单删除流程

```
用户点击「订单删除」→ 弹出删除弹窗
  → 选择/拖拽 CSV/TXT 文件
  → 解析工号列表，自动跳过表头
  → 预览匹配到的工号（红色标记）
  → 点击「确认删除」
  → 删除所有匹配工号的候补记录
  → 弹窗显示结果：移除 X 条，匹配 Y 个工号
  → 数据保存 → 界面实时刷新
```

## 8. 非功能需求

| 项目 | 要求 |
|------|------|
| 性能 | 支持 1000+ 条候补记录流畅操作，拖拽无卡顿 |

| 部署 | 纯前端静态部署，无需后端服务 |

## 9. 已知限制与后续规划

### 9.1 当前限制

- **数据不共享**：LocalStorage 单设备存储，无法多人协作
- **无权限控制**：任何访问者可操作所有数据
- **无操作日志**：递补/删除操作不可追溯
- **无撤销机制**：除二次确认外，操作后无法回退

### 9.2 后续规划（优先级排序）

| 优先级 | 功能 | 说明 |
|--------|------|------|
| P0 | 后端数据持久化 | 接入数据库，支持多设备同步 |
| P0 | 多用户协作 | 多人同时操作，数据实时同步 |
| P1 | 操作日志 | 记录所有递补/删除操作，支持审计追溯 |
| P1 | 撤销/回退 | 支持递补操作撤销，恢复候补状态 |
| P2 | 权限管理 | 管理员/操作员角色分离 |
| P2 | 递补规则引擎 | 支持按候补时间排序自动递补，而非纯手动拖拽 |
| P3 | 移动端适配 | 响应式布局优化，支持触屏操作 |
| P3 | 数据看板 | 剧目维度的递补率、候补趋势等可视化报表 |
